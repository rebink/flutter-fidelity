---
name: screenshot-to-flutter
description: Generate maintainable Flutter screens from reference PNGs and supplied fonts/assets, including when Figma layers and metadata are unusable. Use with Flutter Fidelity capture and comparison tools.
---

Use the PNG as the visual authority. Figma/Sketch metadata is optional assistance, never a prerequisite. This skill is executed by the coding assistant with vision; the MCP server does not infer layouts or generate Dart by itself.

1. Read [the workflow](../../docs/workflow.md) for tool arguments and the visual-spec contract. Run `doctor`. Inspect the PNG with `suggest_viewport` and establish logical dimensions, app-content crop, safe areas and export scale once. Use the developer's supplied profile; when they delegate reference selection for a demo, state the chosen benchmark profile and record unavailable source metadata as uncertainty. Otherwise ask for missing dimensions. Do not infer that image pixels equal logical pixels.
2. Import PNG, font files and available assets with `import_reference`. Missing fonts can permit investigation but cannot earn a complete typography pass. Read the original reference image through `inspect_reference` (its returned preview may be downscaled).
3. Inspect the target Flutter repository and current theme/components before generating. Infer a `VisualSpec` with stable region IDs, visible text, logical bounds, layout notes and provenance. Save via `inspect_reference.visualSpec`. Mark unreviewed or ambiguous observations medium/low confidence; do not upgrade guesses solely to make a report pass.
4. Use supplied original assets. `crop_asset` is permitted only for isolated decorations; inspect baked backgrounds and verify scaling. Never render a screenshot of a control, text block or whole screen as the implementation.
5. Generate real text and interactive controls; use flow/constraints for normal layout, overlays for actual overlapping elements, and reusable widgets for repeated patterns. Match font weights, line breaks, letter spacing, fills and effects. Preserve repository architecture and keep presentation separate from business logic.
   For charts, reconstruct axes/labels as text and curves/fills as vector drawing. Sampling a clearly isolated plot stroke into vector coordinates is permitted; preserve the measurements and mark the underlying series as unknown. Do not bake chart labels, controls or an entire chart into an image. Verify interaction indexing against the reconstructed point count. For internet references, preserve the source URL, designer credit, original image and crop; distinguish referenced screens from supplemental screens without a matching reference.
6. Add a development capture entrypoint with the supplied Dart harness and stable `FidelityRegion` IDs. Region boxes must use the same coordinate meaning as the reviewed visual spec. Include exact fonts in native test assets. In widget capture tests, set `debugDisableShadows = false` (restore it in a `finally` block before the test body exits) and await `precacheImage` inside `tester.runAsync` for image assets before capturing; `pumpAndSettle` alone can finish before asset decoding. Keep harness dependencies in dev_dependencies; production entrypoints must not require it.
7. Capture, compare, then follow flutter-visual-repair for bounded correction. Final delivery includes code, report, remaining uncertainties, and independent interaction/accessibility/responsive results. A widget-test pass does not establish Android/iOS renderer fidelity.
